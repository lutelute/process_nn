# process_nn をゼロから再現するためのプロンプトガイド

このリポジトリ（機械学習 77 テーマ＋GPT-2 ビューアの「動くインフォグラフ」集）を、
**AI コーディングエージェント（Claude Code / Codex 等）への指示だけで再現する**ための手順書です。

そのまま貼れるプロンプトを ▶ で示します。フェーズ順に貼っていけば、同じ形のものが出来上がります。
「なぜその指示なのか」を各所に添えてあるので、別テーマ（例：制御工学の可視化集）へ転用するときは
**§2 の憲章だけ書き換えれば**流用できます。

---

## 0. 再現物の定義（＝完成の受け入れ条件）

AI に作らせる前に「何ができたら完成か」を数値で固定します。曖昧なままだと必ず発散します。

| 観点 | 条件 |
|---|---|
| 成果物 | 静的サイト（`index.html` ＋ `viz/*.html` 77 本 ＋ `gpt2/index.html`）。ビルド不要 |
| 依存 | **教材ページは外部依存ゼロ**（ライブラリ・画像・fetch・CDN 禁止。共有は `viz/theme.css` と `viz/nav.js` のみ） |
| 中身 | 各ページは **13〜16 枚のスライド**／3〜4 章／**1 枚 1 核心** |
| 正しさ | 見せかけの乱数アニメ禁止。**その場で実際に学習・計算**する（SGD/Adam、厳密 Shapley、実 MCTS 等） |
| 対比 | 各ページに **A/B 対比**（条件を変えると結果が変わる）を必ず 1 つ以上 |
| 誤解潰し | 各ページに「⚠ よくある誤解」を ✗→✓ で 2 組 |
| 検証 | `npm run verify` 合格＋Playwright で全ページ console error 0 件 |
| 公開 | GitHub Pages（`.nojekyll` 必須）／CI（`.github/workflows/verify.yml`）が緑 |

## 2. 憲章プロンプト（毎回の先頭に貼る不変制約）

これが**このプロジェクトの心臓**です。P4 以降のすべてのプロンプトの先頭に貼り直します
（エージェントは長い会話で制約を忘れるので、毎回貼るのが最も安上がりな品質保証です）。

▶ **CHARTER**

```
【プロジェクト憲章 — 以下は毎回守る不変の制約】

■ 目的
機械学習の「学習の過程」と「内部構造」を、フレームワークに頼らず素の JavaScript で
実装して可視化する教育用の静的サイトを作る。読者は初学者。ブラウザで開くだけで動く。

■ 絶対制約
1. 外部依存ゼロ。ライブラリ・CDN・画像・fetch・npm パッケージを教材ページで使わない。
   共有してよいのは viz/theme.css（配色）と viz/nav.js（ナビ・数式整形・a11y）だけ。
2. 実計算のみ。学習が主題のページは本当に重みを更新する。乱数で「それっぽく」動かすのは禁止。
   構造説明が主題のページは「固定順伝播・簡略版」と明記する。
3. Math.random() 禁止。mulberry32 系のシード付き rng() を使う。再抽選は seed を進めて再計算する。
4. 1 枚 1 核心。盛らない。要素を足すほど分かりやすくなる、は誤り。迷ったら削る。
5. 平均的な見せ方より「条件 A vs 条件 B の対比」で本質を見せる。
6. 日本語・です/ます調。専門用語には平易な言い換えを添える（例：「regret（機会損失）」）。
7. 色は CSS 変数経由（getCSS('--accent') 等）。テーマ外の色を発明しない。canvas 背景は #fffdf6 系。
8. window.__prefersReducedMotion が真ならアニメを飛ばして最終状態を描く。
9. 数式は .eq 内に <i>変数</i>/<sub>/.frac を使い、必ず <span class="read">読み：…</span> の
   読み下し行を添える。
10. 横断的な仕様変更（全ページに効かせたいもの）は個別ページを触らず viz/nav.js に集約する。

■ 禁止事項
- ハルシネーションした数値を本文に書かない。掲載する数値は必ず実行して得た実測値にする。
- 「実装しました」と報告する前に、必ず検証コマンドを走らせて結果を貼る。
```

## 5. P2 — 基盤 3 点セット

全ページが依存する土台を先に作ります。**参照実装を 1 本作ってから量産**するのが要点で、
これを飛ばすと 70 本がバラバラの見た目・構造になります。

▶ *(CHARTER)*

```
基盤を 3 つ作る。順に、それぞれ完成させてから次へ進むこと。

【1】viz/theme.css — ノート/仕様書テーマ
  クリーム紙 (--bg:#faf8f1) ・インク色 (--text:#1a1a17) ・モノスペース見出しの
  「方眼ノート」風。CSS 変数で全色を定義する:

  --accent(#1f9e8a teal) --warm --neg(#cf4f5f) --loss --upd
  --mincho --gothic --mono（Noto Sans JP / JetBrains Mono 系のフォールバック付き）
  以後、配色の変更はこのファイルだけで完結すること。

【2】viz/nav.js — 全ページが読み込む唯一の共有 JS
  役割を 1 ファイルに集約する（後から全ページへ一括で効かせるための仕組み）:
  (a) カテゴリ折りたたみナビの注入。現在ページのカテゴリだけ展開、他は名前だけ表示し
      クリックでその場展開（再読込なし）。カテゴリ定義は const cats = [...] に持つ。
  (b) 数式の見た目を一括で教科書品質に。inline の .eq{font-family:mono} を
      body .eq の詳細度で上書きし、セリフ体＋斜体変数に。.frac(分数)/.rad(根号)/.mvar を提供。
  (c) <span class="read">…</span> の読み下し行を整形。
  (d) アクセシビリティ底上げ：二次テキストのコントラストを AA まで暗色化、
      キーボードフォーカスの可視化（マウス時は出さない）、prefers-reduced-motion で
      CSS アニメ抑制＋ window.__prefersReducedMotion を公開。
  (e) ページ末尾に「← 前のテーマ／次のテーマ →」の学習順路フッターを注入。
  すべて「theme.css より後勝ちの注入」にして、どのページにも確実に届くようにする。

【3】viz/_template.html — 参照実装（1 ページ目の教材を兼ねる）
  骨格の順序は固定:
    head: charset/viewport/title/inline <style> → <link rel="stylesheet" href="theme.css">
    body .wrap:
      .nav（空。nav.js が注入）
      h1
      .lead 導入 2〜3 文（<b>強調</b> と関連ページへの <a>）
      .purpose 3 行固定（なぜ学ぶ? / 一言で言うと / どこで使われる?）
      .stage
        .stepper#stepper（章タブ 3〜4）
        .body → .vis(canvas#cv 360x430 ＋ .mini ＋ .legend) ／ .explain#explain
        .bar（前へ／次へ(primary)／自動／最初から ＋ spacer ＋ ページ固有操作）
      .aha 💡 見方が変わる一文（1 文）
      .myth ⚠ よくある誤解（✗誤解 → ✓正しい理解 を 2 組）
      <details> もっと詳しく（数式の詳細・限界・関連手法）
      <script>"use strict"; 本体</script>
      <script src="nav.js"></script>
  スライドエンジン:
      const CHAPTERS=[{t:'Ⅰ …',c:'var(--neg)',start:0},…]   // 3〜4 章
      const SLIDES=[{title,legend,html(),draw(),dice?},…]     // 13〜16 枚
      html() は <h3> ＋ .eq.curr（数式）＋ .desc（本文）を返し、学習中のライブ値を文中に埋める

### 7.3 なぜ「先に Node で数値を確かめる」のか

教材の主張（例：「UCB は regret が対数的、欲張りは直線」）が**そのシードで本当に出るか**は、
実装するまで分かりません。単一試行だと運で主張と逆の絵になることがあり、
実際に「ε スイープが単一試行では ε=0.4 が最良に見えて誤解潰しと矛盾 → 30 回平均に変更」という
修正が発生しました。**先に実測 → その数値で本文を書く**と、この手戻りが消えます。

> ⚠ **Node とブラウザで数値がズレることがある**：カオス的な学習（強化学習系）では
> Math 実装差で結果が変わります。掲載する数値は「動的に表示する」か「ブラウザで実測して確定」に
> してください（Node の実測値をハードコードしない）。

## 9. P6 — 検証基盤（できれば P4 の前に作る）

「動きました」を人手で確認し続けるのは破綻します。**検証を先に用意**してください。

▶

```
検証ツールを tools/ に作る。依存は Node 標準と playwright のみ。

1. tools/check-pages.mjs — 全ページの静的健全性（依存パッケージなし）
   ① リンク切れ: href/src が指すローカルファイルの実在

3. tools/crawl-pages.mjs — Playwright で全ページを開き、console error /
   未捕捉例外 / リクエスト失敗を 0 件で通す

## 10. P7 — 横断磨き込み（全ページに一括で効かせる）

70 本できてから「全ページに ○○ を足したい」となります。**個別ページを 70 回編集させない**のがコツで、
`viz/nav.js` に注入すれば後勝ちで全ページに届きます。

▶

```
全ページ横断の改善を入れる。原則: 個別ページを編集せず viz/nav.js への注入で実現する
（inline <style> / theme.css より後勝ちなので確実に届く）。

- 数式の見た目を教科書品質に（セリフ＋斜体変数、.frac / .rad）
- アクセシビリティ: 二次テキストのコントラストを AA、フォーカス可視化、reduced-motion
- 学習順路フッター（← 前のテーマ／次のテーマ →）
- ページ末の関連リンク

nav.js で実現できないもの（本文に依存する内容）だけ、個別ページを触る:
- ⚠ よくある誤解（✗→✓ を 2 組）— そのページの本文の用語に合わせるので共通化できない
- 解釈付き注釈 — 本文の導入直後に、そのページの 3〜4 語について
  「原語の分解 → なぜこの名前？ → 人間の感覚でいうと → なぜ必要か → Coffee Break」を直接表示する。
  用語の定義自体は viz/lib/term-notes.mjs に一元化し、ページ側は語を指定するだけにする
  （別の用語集ページへリンクで逃がさない。読者にページを離れさせない）。
  「なぜこの名前？」は名前の由来。専門語の名前はたいてい設計思想の要約なので、
  そこを言語化すると用語が記号でなく意味の塊になる（例: GAN＝生成器と識別器を敵対させる
  枠組みそのものが名前。adversarial example とは別概念）。
```

**用語ノートの増やし方（テンプレ）** — 3 行足すだけで、その語を載せる全ページに反映されます。

```js
// 1) viz/lib/term-notes.mjs の TERM_NOTES へ 1 行（語そのもの）
T('gan','GAN','Generative Adversarial Network','生成・表現学習',
  'generative=生成する|adversarial=敵対的|network=ネット',
  '生成器と識別器を競わせ、生成データを本物分布へ近づけるモデル。',   // 人間の感覚でいうと
  '明示的な尤度計算なしに、鋭い標本を生成する学習信号を得るため。',   // なぜこの考え方？
  '偽造者と鑑定士のいたちごっこ。均衡が崩れると mode collapse が起きる。', // COFFEE BREAK
  ['Goodfellow et al. (2014)','https://arxiv.org/abs/1406.2661']),

// 2) 同ファイルの TERM_NAMING へ 1 行（なぜこの名前？）
'gan': '原論文 Generative Adversarial Nets の直訳。adversarial は生成器と識別器が利害の反する二人ゲーム（ミニマックス）を戦うことを指し、入力に細工をする adversarial example（敵対的サンプル）とは別概念。',

// 3) 同ファイルの PAGE_TERMS へ 1 行（どのページに 3〜4 語出すか）
'viz/gan.html':['gan','generative-model','probability-distribution'],
```

書き方の約束（詳細は `docs/BLUEPRINT.md` の 2.4）: 由来は断定せず確実な事実（頭字語の展開・人名・借用元の分野）を軸に、
1〜2 文 140 字以内。原語の分解の言い換えにしない。COFFEE BREAK と内容が重なったら片方の角度を変える。
未記入の語は欄ごと非表示になるので、部分的に増やしても表示は崩れません。

## 13. 言い直し集（実際に効いた指摘の言葉）

エージェントの出力がズレたとき、**この言い方で戻ります**。抽象的な「もっと良くして」は効きません。

| 症状 | 効いた指示 |
|---|---|
| 要素を足しすぎて読めない | 「**可視化しすぎ**。学習性を上げようとして要素を盛るのは逆効果。1 ページ 1 核心に削って」 |
| 図が何を言いたいか不明 | 「平均のヒートマップでは本質が見えない。**条件 A と B の対比**にして。例：LSTM なら 2 系列が分かれて保持される様子」 |
| 専門用語が硬い | 「専門名には**平易な言い換え**を必ず添えて（regret（機会損失）のように）」 |
| 全ページに同じ修正が要る | 「個別ページを触らないで。**viz/nav.js に注入**すれば後勝ちで全ページに効く」 |
| 数値が怪しい | 「その数値はどこで実測した? **Node かブラウザで実行して**、出力を貼って。合わないなら本文を直して」 |
| 動くけど中身が空 | 「アニメが乱数で動いているだけになっていない? **本当に重みが更新されているか**を、学習前後の重みを出力して示して」 |
| ハブが静かすぎる | 「トップは**自動再生**にして。ただし各ビューアは静止のままでいい（予想させる設計）」 |
| 3D を消したくなる | 「3D は消さず**構造トラック**として残す。過程 = 2D / 構造 = 3D の役割分担にする」 |

## 付録：この構成が採用している設計判断

再現時に「なぜそうなっているか」を知っておくと、崩さずに拡張できます。

- **外部依存ゼロ** — 教材は 5 年後も動く必要がある。CDN もフレームワークも壊れる。3D すら自前（`viz/lib3d.js`）。
- **共有 JS は nav.js 1 本だけ** — 「全ページに効かせたい」が来たとき、触る場所が 1 箇所に決まる。
- **初期表示は静止** — 読者に「次はどうなる?」と予想させてから見せるため。ハブだけは例外で自動再生。
- **A/B 対比が必須** — 平均的な図は「見た」で終わる。条件を変えて結果が変わると「分かった」になる。
- **myth（誤解潰し）が必須** — 直感と逆になる箇所が各手法に必ずあり、そこを外すと誤解したまま進む。
- **解釈は本文内に置く** — 用語集へのリンクにすると読者はページを離れて戻ってこない。
- **登録 4 面を規約化** — 作っただけで導線がないページは存在しないのと同じ。
- **7+7 ループ** — 「充実だけ」だと嘘が混ざり、「検証だけ」だと薄いまま。交互に回すのが最短。
